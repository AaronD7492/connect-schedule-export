# Connect Schedule Export

Export your Amazon Connect agent schedule to an `.ics` calendar file, entirely in your own browser.
It's built for phones: install the bookmarklet, open your Agent Schedule page, tap the bookmark and download.

- **Private:** no network calls and no server. It never reads login details. Only your settings are saved, in your own browser.
- **Read-only:** the only things it clicks are the Next week and Previous week buttons.
- **Works with any calendar:** Apple Calendar, Google Calendar, Outlook, Android calendars.

Install page: GitHub Pages, served from the `docs/` folder (see "Publishing").

## How it works

1. It reads each activity's screen-reader description and element ID on the Agent Schedule page.
2. It moves forward week by week until it finds 14 empty days in a row, then returns to the week you started on.
3. It keeps only the activity types listed in `src/core/registry.js` (On Queue, On Queue - In Office, Meal, Project). Anything else, such as Paid Absent, is treated as time not worked and named in the summary.
4. It builds an RFC 5545 calendar file with UTC times. Event IDs come from Connect, so re-importing updates events instead of duplicating them.

Design documents: Phase 1 Analysis and Design Document (shared separately).

## Development

Requirements: [Node.js](https://nodejs.org/) 20 or later (LTS recommended).

```bash
npm install      # dev tools only: esbuild, jsdom
npm test         # unit and page tests (Node's built-in test runner)
npm run build    # writes dist/ and docs/index.html
```

### Project layout

```text
src/
  core/        parser.js, registry.js, collector.js, icsBuilder.js   (no browser code; tested in Node)
  adapters/    pageReader.js, weekNavigator.js                       (the only code that knows the page layout)
               download.js, settings.js                              (browser services)
  ui/          panel.js                                              (export panel, in its own shadow root)
  main.js      entry logic;  bookmarklet.js  bundle entry
tools/probe.js            live-page diagnostic
scripts/build-bookmarklet.js
test/                     *.test.js and fixtures/ (saved page with name and IDs replaced)
docs/template.html        install page template; docs/index.html is generated by the build
```

### Adding an activity type

Add an entry to `DEFAULT_WORK_TYPES` in `src/core/registry.js`. No other code changes are needed.

### If Amazon changes the page

Only `src/adapters/pageReader.js` (selectors and reading) and `src/adapters/weekNavigator.js` should need changes.
Run the diagnostics bookmarklet on the live page to see what changed, save a new copy of the page as a fixture, and update the tests.

## Testing on the live page

Run `tools/probe.js` on the Agent Schedule page: paste it into the browser console (F12), or use the Diagnostics bookmarklet from the install page.
It reports whether the schedule can be reached, whether activity descriptions match, and whether week navigation works.

## Branches and publishing

| Branch | Purpose | Install page |
| --- | --- | --- |
| `main` | Stable, tested version for agents | `https://<user>.github.io/connect-schedule-export/` |
| `dev` | Work in progress | `https://<user>.github.io/connect-schedule-export/dev/` |

GitHub Actions (`.github/workflows/pages.yml`) runs the tests and builds both pages on every push to either branch.
If the tests fail, nothing is published. The dev page has a warning banner, "(dev)" in the bookmark name and a `-dev` version number in the panel.

Do new work on `dev`. When it's tested, merge `dev` into `main` to release it.

One-time setup on GitHub:

1. Settings → Pages → Source: **GitHub Actions**.
2. Settings → Environments → `github-pages` → Deployment branches: add `dev` next to `main`.

`npm run build` locally writes `docs/index.html` for previewing. That file isn't committed.

## Privacy notes for contributors

Never commit a saved schedule page without replacing names and activity IDs. Never add a company instance URL to the code.
